- 2026-11-21 to 2026-11-22 · **[CPMM chapter](/docs/en/products/cpmm):** Corrects all seven CPMM pages. A [follow-up pass](#follow-up-pass-on-22-november) corrects one claim from the first, fixes 16 pages outside the chapter that repeated the old claims, measures Stable AMM and routing compute, and tests the code examples against the published SDK. No upstream PR has been opened. The changes are in this checkout.

**In short.** CPMM is Raydium's default constant-product pool. Its docs were broadly right about the program's design but wrong in many details that integrators act on. They said every fee tier's creator fee and the protocol's share of it default to zero. On mainnet, every tier had a nonzero configured creator-fee rate, but only pools created with the fee enabled charged it; 213 of the 615 sampled pools had it enabled. Tiers 0–20 defaulted to a 5% protocol share, subject to per-creator overrides. The docs also said protocol and fund collection takes no arguments and empties the counters; it takes requested amounts and sends them wherever the signer chooses. Their swap examples copied two SDK quoting bugs that misprice creator-fee pools, and they said the SDK handles Token-2022 transfer fees when it doesn't. The oracle, the LP-supply invariant, several error names and the compute figures were also wrong. This pass brings every CPMM page in line with the program source, the published SDK and sampled mainnet state as of 21 November 2026.

## The live fee settings

The docs treated a fee tier's creator fee and the protocol's share of it as zero unless an admin changed them. On mainnet, every one of the 25 tiers had a nonzero configured creator-fee rate, from 0.05% to about 2.1%, but only enabled pools charged it. Tiers 0–20 defaulted to giving the protocol 5% of collected creator fees; creator-specific override accounts could replace that rate. A creator estimating their payout, or an integrator quoting an enabled creator-fee pool, got the wrong answer. The `cpmm-config` API also listed only 21 of the 25 tiers and did not return the share rate.

## Protocol and fund collection

The docs said `CollectProtocolFee` and `CollectFundFee` take no arguments, empty the counters and pay a fixed protocol destination. The program takes two requested amounts, moves the smaller of each amount and the accrued balance, and pays whichever token accounts the signer passes. The program admin may sign in place of the stored owner.

They decided which side the creator fee is on without looking at the swap direction, and they charged the tier's creator fee even on pools that have it disabled. In the 2026-11-21 sample, 213 of 615 pools had the creator fee on, all of them on `OnlyToken0` (174) or `OnlyToken1` (39), and every tier's rate is non-zero, so both bugs misprice real pools. ## The price oracle

The docs described an observation buffer that appends a new entry per slot from raw vault balances. The program spaces entries at least 15 seconds apart, adds to the newest entry in place between them, and records the fee-excluded price from before each swap. ### How the examples were tested

Nothing was signed or submitted. Both tests are repository scripts with saved results. The first quote comparison on 22 November was a scratch run that was not kept. `scripts/compare-cpmm-quotes.mjs` rebuilt it with a fixed seed, and the counts below are from that retained run.

- **Type-check.** `scripts/typecheck-code-demos.mjs` compiles each TypeScript block on [Code demos](/docs/en/products/cpmm/code-demos) (10 blocks) and [Fees](/docs/en/products/cpmm/fees#reading-fees-from-a-running-pool) (1) as its own module with `strict`, against `@raydium-io/raydium-sdk-v2@0.2.85-alpha` and TypeScript 5.6.3. Variables that earlier blocks define, such as `raydium` and `rpcData`, are declared with the SDK's own types. The [Swap from CLI](/docs/en/quick-start/swap-from-cli) script, which is plain JavaScript, is checked the same way without `strict`. All pass after the `poolInfoList` fix above; without it, that block fails with `Cannot find name 'poolInfoList'`. The result is in `public/tino-changes/evidence/code-demo-typecheck-2026-11-22/`.
- **Quote logic.** `scripts/compare-cpmm-quotes.mjs` compares the SDK's `CurveCalculator`, fed by the documented creator-fee logic, with a BigInt port of the program's swap math. The port covers `curve/calculator.rs`, `curve/fees.rs`, `curve/constant_product.rs`, `checked_ceil_div` in `utils/math.rs`, and `is_creator_fee_on_input` and `adjust_creator_fee_rate` in `states/pool.rs`. The comparison covers all 25 fee tiers, each creator-fee mode with the fee on and off, and both directions. That makes 12,000 seeded random cases for each swap type, each a trade of 0.01% to 10% of a reserve.
  - The documented logic chose the program's creator-fee side in all 24,000 cases, and never charged a creator fee on a pool with it off.
  - Exact-output quotes matched the program exactly.
  - Exact-input quotes matched exactly when the creator fee was off or on the output. With it on the input, 1,096 of 4,000 quotes were lower than the program's, each from a fee one input unit higher. None was higher.
  - Fed `computeSwapAmount`'s logic instead, the SDK matched the program in 1 of the 6,000 exact-input cases with the creator fee off, and 3 of the 6,000 exact-output ones. It matched 40 of the 2,000 exact-input `OnlyTokenA` or `OnlyTokenB` swaps from token A to token B.
- **Read-only runs on mainnet.** The same script quoted two pools through `getPoolInfoFromRpc`, swapping 0.1% of the token A reserve for token B. They were the highest-TVL pools in `pool-lp-supply.csv` with the creator fee on and off. The run completed near slot 472,601,598.
  - On the creator-fee pool, an `OnlyTokenA` pool: the documented logic took the creator fee from the input and quoted exactly what the program pays. `computeSwapAmount` took it from the output and quoted 198,622 output units more than the program pays.
  - On the pool with the fee off: the documented logic charged no creator fee and matched the program. `computeSwapAmount` charged a 50,531-unit creator fee on the input and quoted 28,519,682 fewer output units.
  - The evidence is in `public/tino-changes/evidence/cpmm-quotes-2026-11-22/`.
