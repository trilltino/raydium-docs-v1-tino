## Open

- **11.23.26** · **[SDK issue #235](https://github.com/raydium-io/raydium-sdk-V2/issues/235), `createCustomizablePoolV2` seed index:** Opened 23 November on the TypeScript SDK repo and still open. The builder picks a pool's `seed_index` by taking the first free index from 1 to 100. If all 100 are taken, it falls back to index 1, which already holds a pool. With `forerunCreate` it skips the check and always uses index 1. Both transactions fail, and the builder takes no seed-index parameter to avoid it. The program accepts any nonzero `u16`, so 101 and higher are still free. Today the "all 100 taken" case is unlikely: in the 2,000 highest-TVL pools, the highest index is 4. The `forerunCreate` case already applies to the 165 configuration and mint pairs with a pool at index 1. The evidence is `scripts/check-clmm-seed-index.mjs`, which runs the published `0.2.85-alpha` builder against a stubbed RPC, and its output in `public/tino-changes/evidence/clmm-seed-index-2026-11-23/`. The docs previously said only that the builder picks the first free index; both pages now warn about the two failing cases:
  - **[CLMM code demos, Create an additional seed-indexed pool](/docs/en/products/clmm/code-demos#create-an-additional-seed-indexed-pool):**
    - **Was:** "In SDK `0.2.85-alpha`, the V2 builder checks the first 100 nonzero seed indexes and selects the first available one. This is SDK behavior, not a permanent CLMM program rule."
    - **Now:** the same text, then "The builder takes no seed-index parameter. In two cases it builds a transaction that fails, because a pool already exists at the index it picks" … "If indexes 1 to 100 are all taken, it falls back to index 1. The program would accept 101 or higher." … "With `forerunCreate: true`, it skips the check and always uses index 1. Don't use that option for a configuration and mint pair that already has a seed-indexed pool."
  - **[TypeScript SDK, CLMM customizable pools and limit orders](/docs/en/sdk-api/typescript-sdk#clmm-customizable-pools-and-limit-orders):**
    - **Was:** "The SDK checks the first 100 seed indexes and selects the first available one."
    - **Now:** "The SDK checks the first 100 seed indexes and selects the first available one. If all 100 are taken, it falls back to index 1, and `forerunCreate` always uses index 1. Both fail when index 1 already holds a pool."
- **11.22.26** · **[Issue #36](https://github.com/raydium-io/raydium-docs-v1/issues/36), compute-unit figures:** Opened 22 November and still open. Reports that the compute figures for AMM v4, CPMM, CLMM, routing and Stable AMM don't match mainnet. The priority-fee and transaction tables are 3–9× too high, and the Stable AMM figure at least 6× too low. Five statements are wrong, including that CPMM is cheaper than AMM v4 and that a Compute Budget instruction costs 5,000 CU. Each figure was measured on 9 September and on 22 November with `scripts/measure-compute.py`; the evidence is in `public/tino-changes/evidence/`.
