- 11.20.26 · **[AMM v4 chapter](/docs/en/products/amm-v4):** Corrects all seven AMM v4 pages. No upstream PR has been opened. The changes are in this checkout.

**In short.** AMM v4 is Raydium's original pool program. Two upgrades changed it: in **July 2026** Raydium removed its link to the **OpenBook** order book, and in **September 2026** it rebuilt the program for Solana 3.0. The docs still described the old program in places. Readers and integrators got wrong answers about how fees are taken, which accounts to pass, what the SDK sends and what a swap costs. This pass brings every AMM v4 page in line with the program as it runs today.

**How to read this page.** Each change links to the section it touched and to the source that supports it. **Was** quotes the old wording and **Now** quotes the new wording, both exactly; "…" marks a cut.

## The OpenBook link is gone

AMM v4 was originally designed to place buy and sell orders on an **OpenBook** market, an on-chain order book. Raydium deleted that code in July 2026. The program still **accepts** the old market accounts so existing integrations keep working, but it **reads nothing from them**. Several pages still described the order book as live, which sent integrators after accounts and behaviour that no longer matter.

## The protocol fee is not split per swap

The docs said each swap splits its default **0.25% fee** on the spot: 0.22% to liquidity providers and 0.03% to the protocol. The program does not do that. The **whole fee stays in the pool** and grows its reserves. With the default parameters, the protocol takes its **12% share of that growth later**, when someone deposits, withdraws or sweeps fees. This matters to anyone who reads the pool's fee counters, quotes from its reserves or tracks what liquidity providers earn: the counters lag behind, and the pool's `k` shrinks a little each time the protocol takes its share.

## Fees can change after a pool is created

The docs said a pool's fees are **fixed at creation**. Every pool does start with the same defaults, but the **admin can change any pool's fees later**. An integrator that hardcodes the defaults could quote the wrong price.

## Compute costs after the rebuild

The prior docs carried compute estimates from before the September rebuild. The new figures come from mainnet on 20 November 2026.

**How to reproduce.** Take the 400 most recent successful transactions for the AMM v4 program and for the CPMM program. In each transaction's logs, find the pool program's line `Program <id> consumed N of M compute units`. N is that swap's compute, including the pool's own token transfers. Take the median per swap type. Any single transaction's logs in a Solana explorer show the same line.

**Results.** Median consumption was 15,397 CU for 98 AMM v4 `SwapBaseInV2` swaps, 16,091 CU for 34 v1 `SwapBaseIn` swaps, and 25,152 CU for 384 CPMM `swap_base_input` swaps. Swaps in five blocks either side of the AMM v4 redeploy at slot `445763204` (slots `445762804`–`445762808` and `445763604`–`445763608`) dropped from a median of 25,681 CU to 15,404 CU.
