<Info>
  As of the 2026-07 upgrade, AMM v4's OpenBook / Serum dependency has been **removed** — no instruction reads or writes OpenBook state anymore. The market accounts below are retained only as positional placeholders on the legacy v1 instruction layouts (accepted but ignored) and as reference fields on `AmmInfo`. Use the V2 swap entrypoints, which omit them entirely. This page still groups the accounts into "pool-owned" and "OpenBook (legacy)" sections for reading older transactions.
</Info>

## Inventory

Each pool's `AmmInfo` stores the `market` key supplied at creation. Since the OpenBook removal, the program uses that key only as a seed for the pool's addresses. The pool is not bound to a market.

| Category | Account | Owner | Role |
|----------|---------|-------|------|
| Program | `AmmConfig` | AMM v4 program | Program-wide config: `pnl_owner` and `create_pool_fee`. One per program. See [`AmmConfig`](#ammconfig). |
| Program | `amm_authority` | — (never allocated by AMM v4) | PDA `["amm authority"]` that the program signs with. The program uses the derived address as a shared signer authority; it does not initialize account data there. |
| Pool | `AmmInfo` | AMM v4 program | Pool state: fees accrued, status, references to vaults (and, as legacy fields, the market). |
| Pool | `amm_target_orders` | AMM v4 program | Holds `calc_pnl_x` / `calc_pnl_y`, the baseline the protocol fee is measured from. `Deposit`, `Withdraw` and `WithdrawPnl` read and rewrite it. Its order-grid fields are legacy. See [`TargetOrders`](#targetorders). |
| Pool | `pool_coin_token_account` | SPL Token | Pool's coin-side vault: a PDA token account owned by `amm_authority`, not an ATA. See [Vaults](#vaults). |
| Pool | `pool_pc_token_account` | SPL Token | Pool's pc-side vault, derived the same way. |
| Pool | `lp_mint` | SPL Token | Fungible LP mint. |
| Legacy | `amm_open_orders` | OpenBook | Legacy `OpenOrders` reference. Never created or read by the current program, which writes `AmmInfo.open_orders = Pubkey::default()` on every new pool; only pools created before the OpenBook removal carry a real value. Still passed positionally on v1 layouts. |
| Legacy | `market` | Any (an OpenBook market on older pools) | Seed for the pool's PDAs, stored as `AmmInfo.market`. On v1 layouts its slot is read and ignored. |
| Legacy | `market_program` | — | The OpenBook program ID. Read and ignored on v1 layouts; new pools store `Pubkey::default()` in `AmmInfo.market_program`. |
| Legacy | `market_bids`, `market_asks` | OpenBook | Bid/ask queues. Ignored. |
| Legacy | `market_event_queue` | OpenBook | Pending events. Ignored. |
| Legacy | `market_coin_vault`, `market_pc_vault` | SPL Token | Market-level vaults. Ignored. |
| Legacy | `market_vault_signer` | OpenBook | Market-level PDA. Ignored. |

The program names these accounts with a `market` prefix: `AmmInfo.market` and `AmmInfo.market_program` in `state.rs`, and `market_bids` through `market_vault_signer` in `instruction.rs`. Raydium publishes no AMM v4 IDL; [`raydium-idl`](https://github.com/raydium-io/raydium-idl) covers CLMM, CPMM and LaunchLab only.

## `AmmInfo`

The pool's root state account, exactly 752 bytes. It is a `#[repr(C, packed)]` struct with no discriminator, so every field sits at a fixed offset.

```rust program/src/state.rs
pub struct AmmInfo {
    pub status: u64,           // AmmStatus value, not a bitmask; see Status below
    pub nonce:  u64,           // bump used to derive amm_authority
    pub order_num: u64,
    pub depth: u64,
    pub coin_decimals: u64,
    pub pc_decimals:   u64,
    pub state:         u64,    // internal state machine
    pub reset_flag:    u64,
    pub min_size:      u64,
    pub vol_max_cut_ratio: u64,
    pub amount_wave: u64,
    pub coin_lot_size: u64,    // legacy (OpenBook lot size); now initialized to 0
    pub pc_lot_size:   u64,    // legacy; now initialized to 0
    pub min_price_multiplier: u64,
    pub max_price_multiplier: u64,
    pub sys_decimal_value: u64,

    pub fees: Fees,            // trade/protocol/fund fee rates
    pub state_data: StateData,

    // Pool-owned accounts:
    pub coin_vault: Pubkey,
    pub pc_vault:   Pubkey,
    pub coin_vault_mint: Pubkey,
    pub pc_vault_mint:   Pubkey,
    pub lp_mint:  Pubkey,
    pub open_orders: Pubkey,   // legacy; Pubkey::default() on pools created since the removal
    pub market: Pubkey,        // seed for the pool's PDAs; an OpenBook market on older pools
    pub market_program: Pubkey, // legacy; Pubkey::default() on pools created since the removal
    pub target_orders: Pubkey, // TargetOrders account; holds the protocol-fee baseline
    pub padding1: [u64; 8],     // reserved — NOT withdraw_queue / lp_vault
    pub amm_owner: Pubkey,      // admin (multisig)
    pub lp_amount: u64,         // the pool's internal LP total; see the note below
    pub client_order_id: u64,
    pub recent_epoch: u64,
    pub padding2: u64,
}

pub struct Fees {
    pub min_separate_numerator:   u64,     // 5
    pub min_separate_denominator: u64,     // 10_000
    pub trade_fee_numerator:      u64,     // 25  → legacy (was OpenBook order pricing)
    pub trade_fee_denominator:    u64,     // 10_000
    pub pnl_numerator:            u64,     // default 12; settlement fraction numerator
    pub pnl_denominator:          u64,     // default 100; 12% of calculated pool growth
    pub swap_fee_numerator:       u64,     // default 25; 0.25% gross swap fee
    pub swap_fee_denominator:     u64,     // default 10_000
}

pub struct StateData {
    pub need_take_pnl_coin: u64,        // still updated — accrued protocol fee (coin side)
    pub need_take_pnl_pc:   u64,        // still updated — accrued protocol fee (pc side)
    pub total_pnl_pc:   u64,            // DEPRECATED — no longer updated
    pub total_pnl_coin: u64,            // DEPRECATED — no longer updated
    pub pool_open_time: u64,            // still used — pool open timestamp
    pub padding: [u64; 2],              // reserved
    pub orderbook_to_init_time: u64,    // DEPRECATED — no longer updated
    pub swap_coin_in_amount: u128,      // DEPRECATED — volume counters frozen
    pub swap_pc_out_amount:  u128,      // DEPRECATED
    pub swap_acc_pc_fee:    u64,        // DEPRECATED
    pub swap_pc_in_amount:  u128,       // DEPRECATED
    pub swap_coin_out_amount: u128,     // DEPRECATED
    pub swap_acc_coin_fee:  u64,        // DEPRECATED
}
```

<Note>
  The struct **layout is unchanged** (byte-compatible) so existing deserializers keep working, but after the OpenBook removal the fields marked `DEPRECATED` above are **no longer written** — the `swap_*` volume counters are frozen at their last value. For volume analytics, use trade logs rather than these fields. Only `need_take_pnl_*` and `pool_open_time` are actively maintained.
</Note>

Integrator-facing fields:

- **`coin_vault`**, **`pc_vault`** — the pool's SPL Token vaults. `coin` is `token_0` by Serum/OpenBook convention (base), `pc` is `token_1` (quote).
- **`coin_decimals`**, **`pc_decimals`** — matching the mints.
- **`open_orders`**, **`market`** — legacy reference fields. Still present on `AmmInfo` and still passed positionally on the v1 instruction layouts, but the program no longer reads or validates them. The V2 swap entrypoints omit them.
- **`target_orders`** — not legacy. The program still reads and rewrites that account's protocol-fee baseline on every `Deposit`, `Withdraw` and `WithdrawPnl`. See [`TargetOrders`](#targetorders).
- **`fees.swap_fee_numerator / swap_fee_denominator`** — the combined trade fee. Default `25 / 10_000 = 0.25%`.
- **`status`** — a single enumerated `u64` state gating operations, **not** a bitmask. Admin-settable via `SetParams` with `param = 0` (`Status`). See [Status](#status) below.
- **`lp_amount`** — the pool's internal LP total. It is **not** equal to `lp_mint.supply`: it is exactly one whole LP token (`10^coin_decimals` base units) higher, because that amount is counted at init but never minted. All pro-rata math uses `lp_amount`, so use it too.
- **`amm_owner`** — written at creation from the program's hardcoded admin key, not from the creator.
- **`state_data.need_take_pnl_*`** — protocol fee owed but not yet swept. Only `calc_take_pnl` adds to it, and that runs inside `Deposit`, `Withdraw` and `WithdrawPnl`, not swaps. Between those calls it lags the fees swaps have earned. `WithdrawPnl` pays it out and resets it to zero.

## `TargetOrders`

Each pool has one `TargetOrders` account (`amm_target_orders`), owned by the program and created at `Initialize2`. Most of it is the old order grid (`buy_orders`, `sell_orders`, `target_x` / `target_y`, `plan_*`, `placed_*`), which the program no longer writes.

Two fields are live: `calc_pnl_x` and `calc_pnl_y`. They hold the pool's pc and coin reserves, in normalized units, at the last protocol-fee settlement:

- `Initialize2` sets them to the opening reserves.
- `Deposit`, `Withdraw` and `WithdrawPnl` first call `calc_take_pnl` (`Withdraw` skips it while the pool is `WithdrawOnly`). It compares the current `x · y` with `calc_pnl_x · calc_pnl_y` and credits the protocol's `pnl_numerator / pnl_denominator` share of the growth to `need_take_pnl_*`, unless either side rounds to zero.
- Each of those instructions then rewrites the baseline to the reserves it leaves behind.

The protocol fee therefore accrues lazily. Swaps grow `x · y`, and the protocol's share is booked at the next deposit, withdrawal or `WithdrawPnl`.

## `AmmConfig`

AMM v4 has one program-wide config account: a 544-byte PDA at seed `["amm_config_account_seed"]`, created by the admin with `CreateConfigAccount` and changed with `UpdateConfigAccount`. Its mainnet address is in [`reference/program-addresses`](/docs/en/reference/program-addresses#program-level-config-accounts).

```rust program/src/state.rs
pub struct AmmConfig {
    pub pnl_owner: Pubkey,     // may sign WithdrawPnl, besides the admin
    pub cancel_owner: Pubkey,  // legacy; signed the removed AdminCancelOrders
    pub pending_1: [u64; 28],  // reserved
    pub pending_2: [u64; 31],  // reserved
    pub create_pool_fee: u64,  // lamports Initialize2 charges the pool creator
}
```

`Initialize2` reads it to charge `create_pool_fee`, and `WithdrawPnl` reads it to check the signer. It holds no trading fees; those live on each pool's `AmmInfo.fees`.

## The OpenBook wiring

<Note>
  **Removed.** The OpenBook / Serum dependency has been deleted from the program (2026-07 upgrade). The accounts described in this section are no longer validated or used. They remain as reference fields on `AmmInfo` and as positional placeholders on the legacy v1 instruction layouts. Use the **V2 swap entrypoints** ([`SwapBaseInV2` / `SwapBaseOutV2`](/docs/en/products/amm-v4/instructions)) which skip these accounts entirely.
</Note>

When you call a legacy **v1** `SwapBaseIn` / `SwapBaseOut`, `Deposit`, or `Withdraw` instruction, the account **count** must still match the old layout (the market accounts occupy their historical positions), but their **contents are no longer checked** — no CPI is issued against them. New code should use the V2 swap variants, which do not take these accounts at all.

The program reads these slots into unused `_`-prefixed variables and never inspects them, so there is nothing to decode. Pass the keys recorded for the pool; `raydium.liquidity.getAmmPoolKeys(poolId)` returns them.

Before the removal, `amm_open_orders` was the OpenBook account holding the pool's limit orders on its market, and `amm_target_orders` held the AMM's intended order grid. The `MonitorStep` crank compared the two and placed or cancelled the difference. That crank is gone. `amm_target_orders` survives only as the protocol-fee baseline described in [`TargetOrders`](#targetorders).

## Authority PDAs

There is exactly one `amm_authority` PDA for the entire AMM v4 program. Its seed is trivial (`["amm authority"]`) and its bump is stored on every `AmmInfo`. This authority signs all token moves for all AMM v4 pools.

```ts
const AMM_V4_PROGRAM_ID = new PublicKey(
  "675kPX9MHTjS2zt1qfr1NYHuzeLXfQM9H24wFSUt1Mp8", // see reference/program-addresses
);
const [ammAuthority] = PublicKey.findProgramAddressSync(
  [Buffer.from("amm authority")],
  AMM_V4_PROGRAM_ID,
);
```

There is no second, pool-scoped authority: this one PDA covers everything the program signs. Its bump is `254` on mainnet and is mirrored on every `AmmInfo` as `nonce`; `WithdrawExcessLamports` re-derives it with that nonce hardcoded.

## Vaults

The pool's SPL Token vaults are standard token accounts whose `owner` is `amm_authority`. Not ATAs — their addresses are PDAs derived at `Initialize2` from `[AMM_V4_PROGRAM_ID, market, "coin_vault_associated_seed"]` and `[AMM_V4_PROGRAM_ID, market, "pc_vault_associated_seed"]`. The mint is not a seed, and neither is `amm_id`. Addresses are stored on `AmmInfo`; derivation is a one-time curiosity.

Token-2022 is **not** supported. The program hardcodes SPL Token's program ID for all vault moves. Attempting to bind an AMM v4 pool to a Token-2022 mint fails at `Initialize2` with `InvalidSplTokenProgram`.

## LP mint

A classic SPL Token mint whose authority is `amm_authority`. Total supply tracks LP ownership of the pool; burning LP returns tokens from both vaults pro-rata.

There **is** an in-state mirror: `AmmInfo.lp_amount`. It is not equal to the mint's supply — it sits exactly one whole LP token (`10^coin_decimals` base units) higher, because that amount is counted at init but never minted. Every pro-rata computation in the program divides by `lp_amount`, so use that field rather than the mint's on-chain supply.

## Status

`AmmInfo.status` is a single enumerated `u64` state, **not** a bitmask. Test it for equality. A client that tests `status & 1`, as if bit 0 meant "enabled", mis-classifies every live pool: the normal trading state is `6` (`0b110`), whose bit 0 is clear.

| Value | `AmmStatus` | Swap | Deposit | Withdraw |
|-------|-------------|------|---------|----------|
| 0 | `Uninitialized` | no | no | no |
| 1 | `Initialized` | yes | yes | yes |
| 2 | `Disabled` | no | no | no |
| 3 | `WithdrawOnly` | no | no | yes |
| 4 | `LiquidityOnly` | no | yes | yes |
| 5 | `OrderBookOnly` | no | yes | yes |
| 6 | `SwapOnly` | yes | yes | yes |
| 7 | `WaitingTrade` | yes, once `pool_open_time` has passed | yes | yes |

`Initialize2` writes `7` when `open_time` is in the future and `6` otherwise; a pool at `7` flips itself to `6` on the first swap at or after `state_data.pool_open_time`. A value outside `0..=7` makes `AmmStatus::from_u64` panic.

The Raydium multisig sets the state via `SetParams` with `param = 0` (`Status`); only values `1`–`7` are accepted. (`AdminCancelOrders` has been removed.)

## Observation / oracle

**AMM v4 has no dedicated observation account**, and since the OpenBook removal there is no order-book state to derive one from either. If you need a Raydium TWAP with program support, use CPMM or CLMM — both maintain an `ObservationState` ring buffer. Otherwise, index the swap logs off-chain.

## Deriving a pool's accounts from scratch

AMM v4's pool accounts are plain PDAs keyed on the pool's `market` key — not seeded keypairs, and not per-pair PDAs. Every one of them uses the same three-seed shape `[AMM_V4_PROGRAM_ID, market, <label>]` under `AMM_V4_PROGRAM_ID`:

| Account | `<label>` |
|---------|-----------|
| `amm_id` (`AmmInfo`) | `"amm_associated_seed"` |
| `amm_target_orders` | `"target_associated_seed"` |
| `lp_mint` | `"lp_mint_associated_seed"` |
| `pool_coin_token_account` | `"coin_vault_associated_seed"` |
| `pool_pc_token_account` | `"pc_vault_associated_seed"` |

```ts
const [ammId] = PublicKey.findProgramAddressSync(
  [
    AMM_V4_PROGRAM_ID.toBuffer(),
    marketPubkey.toBuffer(),
    Buffer.from("amm_associated_seed"),
  ],
  AMM_V4_PROGRAM_ID,
);
```

The `market` key is the only variable seed, so one key maps to exactly one AMM v4 pool. The SDK computes these for you with its `getAssociatedPoolKeys` helper (`src/raydium/liquidity/utils.ts` in `raydium-sdk-v2`).

In practice, integrators read the pool's full account set from `GET https://api-v3.raydium.io/pools/info/ids?ids=<POOL_ID>` or from the SDK. Hand-deriving is rarely needed.

## Lifecycle quick reference

| Event | Accounts created | Accounts destroyed |
|-------|------------------|---------------------|
| `Initialize2` | `amm_info`, `amm_target_orders`, both vaults, `lp_mint`, and the creator's LP ATA | — |
| `Deposit` | — | — |
| `Withdraw` | — | — |
| `SwapBaseIn` / `SwapBaseOut` (v1 / V2) | — | — |
| `WithdrawPnl` | — | — |

`Initialize2` is the only instruction that creates a token account for the user. `Deposit` and the swaps expect the user's token accounts to exist already. The SDK adds the ATA-creation instructions to the transaction when one is missing, for example in `addLiquidity`.

Pools and their accounts persist indefinitely. Even if liquidity is fully withdrawn, `AmmInfo` stays.
