<Info>
  A **platform** in LaunchLab is a third-party launch environment built on Raydium's LaunchLab program. Platforms can brand themselves, charge configured fees, restrict permitted launch parameters, and configure migration rights without running a separate on-chain pool program.
</Info>

## Why platforms exist

LaunchLab is a shared launch primitive. The `PlatformConfig` system lets ecosystems, tooling providers, and communities offer branded launch experiences that use the same LaunchLab program and CPMM migration path.

Examples include Raydium's own LaunchLab UI and third-party launch surfaces with their own platform configuration. A token's platform configuration affects its fees, permitted launch parameters, and LP handling; it does not guarantee that an aggregator or wallet will list or route the token.

## The PlatformConfig PDA

Each platform is represented by a `PlatformConfig` PDA derived from the `platform_config` seed and platform admin key. The SDK layout uses these fields:

| Field | Description |
|---|---|
| `platformClaimFeeWallet` | Authorized to claim accrued platform fees. |
| `platformLockNftWallet` | Receives the platform Fee Key when the locked-LP share is nonzero. |
| `platformScale`, `creatorScale`, `burnScale` | Stored LP scales. Under the updated migration flow, the first two combine into the platform locked-LP share and `burnScale` is burned. |
| `feeRate` | Platform fee rate on pre-migration trades, denominated in millionths. |
| `name`, `web`, `img` | Inline platform branding strings. |
| `cpConfigId` | CPMM `AmmConfig` selected for migration. |
| `creatorFeeRate` | Bonding-curve creator-fee rate. |
| `transferFeeExtensionAuth` | Platform authority used by applicable Token-2022 transfer-fee extension handovers. |
| `platformVestingWallet`, `platformVestingScale` | Platform vesting beneficiary and allocation. |
| `platformCpCreator` | Optional CPMM creator-of-record override. The default pubkey leaves the role with the launch creator. |
| `restrictGlobalConfig` | Requires a platform allow record for the selected `GlobalConfig` when enabled. |
| `restrictCurveParam` | Requires the launch to satisfy the applicable `PlatformCurveRule` when enabled. |
| `curveRuleManager` | Wallet allowed to manage platform curve rules alongside the platform admin. |

For byte layout, PDA derivation, rate caps, update rules, and a decode example, see [`products/launchlab/platform-config`](/docs/en/products/launchlab/platform-config).

## Fee and rights separation

LaunchLab has distinct platform, creator, referral, and locked-LP paths:

- **Platform fee:** `feeRate` accrues to the applicable platform fee vault. `platformClaimFeeWallet` claims it through the supported claim instruction.
- **Bonding-curve creator fee:** `creatorFeeRate` accrues to the vault keyed by creator and quote mint. The creator claims it with `ClaimCreatorFee`.
- **Referral fee:** a per-trade `shareFeeRate` pays the supplied referrer's quote-token account. It is bounded by `GlobalConfig.maxShareFeeRate`, not by the platform fee-rate cap.
- **Locked-LP fee:** the current platform Fee Key holder harvests fees from the locked share. This is separate from CPMM creator fees.

```text
Curve trade
  ├─ protocol fee
  ├─ platform fee → platform fee vault
  ├─ creator fee → creator/quote-mint vault
  └─ optional referral fee → referrer quote-token account

CPMM migration
  ├─ platformScale + creatorScale → LP-Lock → platform Fee Key
  └─ burnScale → burned LP

CPMM trading
  ├─ LP trade-fee share → LP positions, including the locked share
  └─ optional creator fee → recorded CPMM pool_creator
```

## Migration configuration

All newly initialized launches use CPMM. `cpConfigId` selects its `AmmConfig`. Existing state created with the legacy migration type can retain its legacy path.

For migrations executed after the 2026-08-17 upgrade, `platformScale + creatorScale` becomes one platform-owned locked-LP position and `burnScale` is burned. Earlier migrations could create a separate creator Fee Key. Completed historical Fee Key records are not rewritten.

`platformCpCreator` determines the CPMM creator-fee beneficiary independently of the Fee Key. CPMM creator fees also require the relevant enablement, nonzero rate, and fee-side settings.

## Launch restrictions

Platforms can apply two independent restrictions:

- **Global-config allowlist:** with `restrictGlobalConfig` enabled, launch transactions need the matching `PlatformAllowConfig` for the selected `GlobalConfig`.
- **Curve rules:** with `restrictCurveParam` enabled, the launch must satisfy the applicable `PlatformCurveRule`. Rule groups support alternative permitted launch shapes; `curveRuleManager` can manage them alongside the platform admin.

These restrictions can narrow protocol and deployment limits. They do not replace `GlobalConfig` validation or make the platform admin an authorized migration wallet.

## Token-2022 and vesting controls

`transferFeeExtensionAuth` affects the transfer-fee authorities used by supported Token-2022 launches. Read the authority handover rules before rotating this field between creation and migration.

`platformVestingWallet` and `platformVestingScale` configure the platform's share of a launch's locked supply. `CreatePlatformVestingAccount` creates the corresponding vesting record separately from launch initialization.

See [`products/launchlab/platform-config`](/docs/en/products/launchlab/platform-config) and [`products/launchlab/vesting`](/docs/en/products/launchlab/vesting) for the detailed rules.

## Registering and updating a platform

The current IDL exposes `CreatePlatformConfig` for initialization and `UpdatePlatformConfig` for supported field updates. The platform admin pays the account rent and signs updates. Fee rates and other fields remain subject to program validation.

Use [`products/launchlab/instructions`](/docs/en/products/launchlab/instructions) for the current instruction interface and [`products/launchlab/platform-config`](/docs/en/products/launchlab/platform-config) for exact parameters and update variants. Do not substitute descriptive names such as `platform_fee_destination` or `platform_fee_bps` for the SDK's actual fields.

## Integrator notes

- **Decode by the real layout.** Use the SDK's `PlatformConfig.decode` example in the technical reference.
- **Read branding from `name`, `web`, and `img`.** There are no `description`, `image_url`, or `tokens_launched` fields in this layout.
- **Include every fee component.** Quotes can need protocol, platform, creator, referral, and Token-2022 transfer-fee accounting.
- **Verify migration outcomes.** Read the CPMM pool, LP lock or burn record, Fee Key owner, and `pool_creator` rather than inferring current ownership from historical rules.
