## The problem LaunchLab solves

Before LaunchLab, launching a token on Raydium required the creator to seed both sides of an AMM pool up front. LaunchLab replaces that opening step with a bonding curve backed by a configured quote mint. Buyers acquire base tokens from the curve, and the accumulated quote and remaining base supply can later seed a CPMM pool.

Initialization mints the full base supply into the launch's base vault and revokes its mint authority in the same instruction. Curve trades move existing tokens from that vault; they do not mint new supply on each buy.

## Lifecycle

```text
             ┌────────────────────────┐
creator  ──▶ │ InitializeV2 or        │  ▸ mints full supply and fixes launch parameters
             │ InitializeWithToken2022 │  ▸ revokes base mint authority
             └────────────┬───────────┘
                          ▼
             ┌────────────────────────┐
             │ PoolStatus::Fund       │ ◀── Buy / Sell against the selected curve
             └────────────┬───────────┘
                          │ funding condition met
                          ▼
             ┌────────────────────────┐
             │ PoolStatus::Migrate    │  ▸ curve trading closed; vesting clock started
             └────────────┬───────────┘
                          │ authorized MigrateToCpswap
                          ▼
             ┌────────────────────────┐
             │ CPMM pool created      │  ▸ LP locked or burned under platform config
             │ PoolStatus::Trade      │  ▸ ordinary CPMM trading can begin
             └────────────────────────┘
```

Reaching the threshold and migrating are separate events. `MigrateToCpswap` requires the `migrate_to_cpswap_wallet` recorded on the selected `GlobalConfig`. An arbitrary trader cannot call it, and there is no permissionless migration bounty. Existing legacy state can use `MigrateToAmm` with its own configured wallet; newly initialized launches are CPMM-only.

## Core accounts

- **PoolState:** launch parameters, supply, real reserves, fees, platform and config links, vesting schedule, and launch status.
- **Base mint and base vault:** the launched token and its unsold or locked supply.
- **Quote mint and quote vault:** the configured collateral and quote proceeds available for fees and migration.
- **GlobalConfig:** curve and deployment limits, protocol fee rate, fee recipients, and authorized migration wallets.
- **PlatformConfig:** branding, platform and creator fee rates, launch restrictions, CPMM configuration, LP scales, and platform-side wallets.
- **VestingRecord:** one record per beneficiary, created separately from launch initialization.

See [`products/launchlab/accounts`](/docs/en/products/launchlab/accounts) for layouts and derivation.

## Pricing model

LaunchLab supports constant-product, fixed-price, and linear-price curve configurations. Price behavior is curve-specific:

- Constant-product and linear curves change price as base supply is bought or sold.
- A fixed-price curve retains its configured price during curve trading.
- All trades still need exact quote, fee, and slippage accounting.

See [`products/launchlab/bonding-curve`](/docs/en/products/launchlab/bonding-curve) for the formulas. Do not apply a monotonic-price statement to fixed-price launches.

## Funding and migration

A launch becomes ready to migrate when its configured funding condition is met. The last qualifying trade changes the state to `Migrate`; it does not create the CPMM pool itself.

The authorized migration transaction then:

1. Checks that the launch is in `Migrate` and uses the matching migration type.
2. Computes the base amount available for liquidity as `supply − totalSellA − totalLockedAmount`, subject to the actual vault balance and program accounting.
3. Deducts applicable protocol, migration, and platform amounts from quote liquidity.
4. Creates the CPMM pool through `InitializeWithPermission`.
5. Mints initial LP to the migration recipient and applies the platform's lock and burn distribution.
6. Moves the launch to `Trade`.

The base mint authority was already revoked at initialization. Migration does not revoke it again. Token-2022 transfer-fee authority handovers are separate and depend on `PlatformConfig`.

## Fees

Curve trades can include independent fee components:

- **Protocol:** `GlobalConfig.trade_fee_rate`, claimed through the protocol fee path.
- **Platform:** `PlatformConfig.fee_rate`, accrued to the applicable platform vault and claimed by `platformClaimFeeWallet`.
- **Creator:** `PlatformConfig.creator_fee_rate`, accrued to the vault keyed by creator and quote mint and claimed with `ClaimCreatorFee`.
- **Referral:** per-trade `shareFeeRate`, bounded by `GlobalConfig.maxShareFeeRate`, paid to the supplied referrer's quote-token account during the trade.

After migration, the CPMM `AmmConfig` controls the trade-fee configuration. A separate CPMM creator fee applies only when enabled with a nonzero rate. Its beneficiary is the recorded `pool_creator`, which can be the launch creator or the platform's configured override.

## Who holds the LP after migration?

LaunchLab uses the platform's stored scales to produce two effective destinations:

- **Platform lock:** for migrations under the updated program, `platformScale + creatorScale` is locked through LP-Lock. One Fee Key goes to `platformLockNftWallet` when this share is nonzero.
- **Burn:** `burnScale` is burned permanently and has no Fee Key holder.

Before the 2026-08-17 upgrade, `creatorScale` could produce a separate creator Fee Key. The upgrade changes future migration execution only; it does not modify completed historical locks. This LP-fee right is separate from CPMM creator fees.

## Important invariants

- **Base supply is fixed from creation.** Initialization mints the full supply and revokes `MintTokens` in the same instruction.
- **New launches are CPMM-only.** Existing legacy state can retain its legacy migration path.
- **Migration is authorized and one-way.** Reaching the threshold does not let any trader migrate, and a completed launch does not return to the curve.
- **Vesting starts at fundraising completion.** The later migration transaction does not restart the vesting clock.
- **Fee rights are separate.** Creator vaults, CPMM creator fees, referrals, and Fee Key LP fees have different beneficiaries and claim paths.
