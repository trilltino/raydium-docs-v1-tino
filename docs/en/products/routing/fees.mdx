## Router fee

The AMM Routing program charges **no fee of its own**. It is a pure orchestrator.

All fees are paid directly to the pools you route through:

- Each AMM v4 hop pays the AMM v4 fee (0.25% split).
- Each CPMM hop pays the CPMM fee (configurable, typically 0.25% split).
- Each CLMM hop pays the CLMM fee (configurable per pool).
- Each stable hop pays the stable-swap fee (0.02% — much lower than AMM v4).

## Total effective fees on a route

If you route through N pools, your total fee is the sum of all N hops' fees, compounded.

**Example:**

Route: USDC → SOL (0.25% fee) → STEP (0.25% fee)

```
Input: 1000 USDC

Hop 1 (USDC/SOL): 0.25% fee
  Fee: 2.5 USDC
  Output to hop 2: ~997.5 USDC of buying power

Hop 2 (SOL/STEP): 0.25% fee
  Fee: ~2.49 STEP-worth
  Output: ~995 STEP-worth

Total cost: ~0.5% (not exactly 0.5%, since fees compound)
```

See the respective pool's fee documentation for exact splits:

- [`products/amm-v4/fees`](/docs/en/products/amm-v4/fees)
- [`products/cpmm/fees`](/docs/en/products/cpmm/fees)
- [`products/clmm/fees`](/docs/en/products/clmm/fees) (if available)
- [`products/stable/fees`](/docs/en/products/stable/fees) (if available)

## Compute cost

The router's compute cost grows with the number of hops. Each hop adds the pool's swap and the router's own work. In a mainnet sample of 400 AMM Routing transactions, taken over ten minutes on 2026-11-22, the router call consumed:

| Route | Median CU | 10th–90th percentile | Transactions |
|-------|-----------|----------------------|--------------|
| 1 hop | 71,698 | 66,624–101,411 | 327 |
| 2 hops | 133,687 | 107,940–160,805 | 67 |
| 3 hops | 181,963 | 148,208–185,916 | 6 |

That total splits into two parts:

- **Router overhead:** about 20,000 CU per hop, not a fixed amount. After subtracting the programs it calls, the router itself consumed a median of 22,713 CU on 1-hop routes, 42,467 on 2-hop routes and 58,944 on 3-hop routes. This includes the cost of making each call.
- **Pool swaps:** each pool program's own consumption when the router called it:

| Pool program and instruction | Median CU | 10th–90th percentile | Hops sampled |
|------------------------------|-----------|----------------------|--------------|
| CLMM `swap_v2` | 47,017 | 44,110–50,959 | 430 |
| CPMM `swap_base_input` | 28,798 | 25,070–29,946 | 33 |
| AMM v4 `SwapBaseIn` (v1) | 16,279 | 16,086–16,279 | 15 |
| Stable AMM `SwapBaseIn` | 94,487 | 85,252–101,539 | 398 |

The router sample made no Stable AMM hops, so the Stable row comes from the program's last 400 successful transactions, on 2026-11-03 to 2026-11-05. It covers swaps the router made (162) and swaps other programs made. CLMM cost rises with each tick array a swap crosses.

A transaction can use at most 1.4M CU. The figures above cover the router call only: ATA creation, wSOL wrapping and compute-budget instructions add to the transaction. Simulate the whole route before you set a compute limit. Each figure is the program's own `Program <id> consumed N of M compute units` log line; the evidence is in `public/tino-changes/evidence/stable-routing-2026-11-22/`.

## Account initialization overhead

Every enabled swap variant routes intermediate tokens through user-controlled ATAs. On each intermediate hop, you must pre-create and provide a user-owned ATA:

- **If the ATA doesn't exist:** ATA program init costs ~5k CU + ~0.00203928 SOL rent per ATA. Initialize it with the SPL Associated Token Account program (or, for wSOL, with [`CreateSyncNative`](/docs/en/products/routing/instructions#createsyncnative-tag-5) tag 5).
- **If the ATA already exists:** no extra overhead.

For a 5-hop route with 4 intermediate tokens, you would need 4 new ATAs if starting fresh = ~20k CU + ~0.00816 SOL.

You can recover the rent of any temporary ATA — most commonly a wSOL ATA used for a single route — by closing it with [`CloseTokenAccount`](/docs/en/products/routing/instructions#closetokenaccount-tag-6) (tag 6) once it has zero balance.
