## Two creation modes

LaunchLab offers two creation paths accessible from [raydium.io/launchpad/create](https://raydium.io/launchpad/create):

| | **JustSendIt** | **Advanced** |
|---|---|---|
| Token supply | Deployment default | Current UI presets: 100M, 1B, or 10B |
| Funding target | Deployment default | Configurable within the selected config and platform rules |
| Curve allocation | Deployment default | Current UI range: 51–80% |
| Vesting | None | Optional, within UI and on-chain limits |
| Post-migration fees | Platform-defined CPMM creator fee and LP policy | Platform-defined CPMM creator fee and LP policy |

These are current Raydium UI choices, not a claim that the program accepts arbitrary values or that every deployment uses the same defaults.

## What creation costs

Keep enough SOL for the complete transaction and any optional initial buy. The wallet simulation and confirmation can include:

- Solana network and priority fees;
- rent for new mint, launch-state, token, and associated accounts;
- charges shown by the selected LaunchLab configuration and platform;
- the optional initial-buy amount and its trading fees.

Review the exact balance changes before signing. A fixed SOL estimate becomes stale when account requirements, rent, priority fees, or platform configuration change.

## JustSendIt mode

JustSendIt uses the selected deployment's defaults and requires fewer inputs.

### What you need

- A connected wallet with enough SOL for the costs above.
- A token name and ticker symbol.
- An image or GIF that meets the UI requirements.

### Steps

1. Go to [raydium.io/launchpad/create](https://raydium.io/launchpad/create) and select **JustSendIt**.
2. Enter the token **name** and **ticker**.
3. Optionally add a **description** and **social links**.
4. Upload a **logo image or GIF**.
5. Optionally enter an **initial buy amount** in SOL. Review the tokens and fees in the resulting transaction.
6. Review the summary and click **Create**.
7. Approve the transaction in your wallet.

Your token launches on the bonding curve in `Fund`. The public SOL configuration's default funding target was 85 SOL when checked on 2026-11-19. Reaching the configured target makes the launch ready for authorized migration; it does not itself complete CPMM pool creation.

## Advanced mode

Advanced exposes the launch parameters supported by the current UI, selected `GlobalConfig`, and platform rules.

### What you need

- A connected wallet with enough SOL for creation, account rent, and any initial buy.
- The token metadata and launch parameters ready before you sign.

Launch parameters such as supply, curve allocation, funding target, and vesting schedule are fixed by the launch transaction. This does not mean every related platform setting or later vesting-account allocation is frozen. Platform admins can update permitted platform fields, and beneficiary vesting records are created through separate instructions.

### Configuration options

#### Token details

- **Name, ticker, logo** — same as JustSendIt.
- **Description and social links** — metadata for supporting launch surfaces.

#### Supply and curve allocation

- **Total supply** — choose from the current 100M, 1B, and 10B Advanced UI presets. The SDK validates six base-mint decimals and the selected config's supply and allocation rules.
- **Curve allocation** — the percentage of supply available for public purchase on the curve. The current UI permits 51–80%.
- **Vested allocation** — any `total_locked_amount` is withheld from both the curve sale and migration liquidity.
- **Migration liquidity** — the remaining base amount is `supply − totalSellA − totalLockedAmount`.

The SDK and program apply more than the visible UI range. They check the selected config's minimum supply, minimum sale amount, minimum migration amount, maximum lock amount, and minimum raise. Platform curve rules can narrow those limits further.

#### Funding target

- The public SOL configuration's default target was **85 SOL** and its minimum was **24 SOL** when checked on 2026-11-19.
- These values belong to that live configuration. Other global configs, quote mints, or platform rules can impose different limits.
- If the funding condition is not met, the launch remains in `Fund` rather than migrating automatically.

#### Current public SOL configuration

The following values were read from `https://launch-mint-v1.raydium.io/main/configs` on 2026-11-19. They are deployment settings, not universal protocol constants.

| Setting | Current value |
|---|---|
| Default supply | 1B |
| Default curve sale allocation | 79.31% |
| Default / minimum raise | 85 SOL / 24 SOL |
| Minimum sale rate | 20% |
| Minimum migration rate | 15% |
| Maximum lock rate in the config | 80% |
| Maximum referral share rate | 1% |

The current Raydium UI separately limits vesting to 30%. Distinguish that interface limit from the selected on-chain config's maximum lock rate.

#### Vesting

Vesting locks part of the token supply and releases it linearly to designated wallets over a schedule.

| Field | Description |
|---|---|
| Total locked amount | Tokens reserved across creator and platform beneficiaries, subject to UI, config, and platform limits. |
| Cliff period | Wait time after fundraising ends before tokens start unlocking. |
| Unlock period | Duration of linear unlock after the cliff. |

The program records the vesting start when fundraising successfully ends and the launch becomes ready to migrate. It does not wait for the later `MigrateToCpswap` transaction. Claims still require the launch to have completed migration.

<Warning>
  Supply, total locked amount, cliff, and unlock period are fixed at launch. A later platform-config update does not rewrite an existing launch's schedule.
</Warning>

**Beneficiary allocation is separate.**

- `InitializeV2` or `InitializeWithToken2022` records the total locked amount and schedule, not a list of beneficiary wallets.
- The creator creates each beneficiary record with `CreateVestingAccount`.
- The platform creates its own record with `CreatePlatformVestingAccount` when applicable.
- Any part of `total_locked_amount` not allocated before the relevant cutoff remains unallocated. Review the full [LaunchLab vesting](/docs/en/products/launchlab/vesting) mechanics before choosing an amount.

#### Post-migration LP and creator fees

When authorized migration creates the CPMM pool:

1. The pool's initial LP tokens are minted to the migration recipient controlled by the launch flow, not left as LP tokens owned by the CPMM pool itself.
2. For migrations under the updated program, `platformScale + creatorScale` determines the locked share. Its Fee Key goes to the configured platform NFT wallet.
3. `burnScale` determines the burned share.
4. No new creator-owned Fee Key is minted merely because you created the token. Creator-owned Fee Keys from migrations completed before the 2026-08-17 upgrade remain historical positions.

Post-graduation creator revenue is separate. It requires you to remain the recorded CPMM `pool_creator`, the pool and `AmmConfig` to enable creator fees, and a nonzero creator-fee rate. A platform can assign the CPMM creator role to `platformCpCreator` instead. See [How creator fees work](/docs/en/user-flows/how-creator-fees-work).

### Steps

1. Select **Advanced** on the creation page.
2. Fill in token details.
3. Select a supported **total supply** and **curve allocation**.
4. Set the **funding target** within the selected config and platform rules.
5. Configure the total vesting amount and schedule if needed. Plan beneficiary records separately.
6. Optionally enter an initial buy amount.
7. Review the curve settings, migration liquidity, platform fee settings, and LP split.
8. Click **Create** and approve the transaction.

## After your token launches

### Monitor curve progress

Your token's LaunchLab page shows curve progress, quote raised relative to the funding target, and current price information where supported by the selected curve.

If the launch does not meet its funding condition, it remains on the curve. Communicate the actual launch state rather than describing migration as guaranteed.

### Migration

A trade that meets the funding condition changes the launch from `Fund` to `Migrate`. The `migrate_to_cpswap_wallet` recorded on the selected `GlobalConfig` must then sign `MigrateToCpswap`. An arbitrary user cannot execute this step, and there is no permissionless caller bounty.

```text
Create → Fund → funding condition met → Migrate
                                        │ authorized migration wallet
                                        ▼
                             CPMM pool + LP lock/burn → Trade
```

After migration, verify the CPMM pool, LP lock or burn records, Fee Key owner, and creator-fee configuration. Claim any available pre-migration creator-fee balance through the Portfolio page.

## Operational pitfalls

| Pitfall | What to check |
|---|---|
| Treating a live config value as a protocol constant | Read the selected `GlobalConfig`, platform config, and current UI constraints. |
| Leaving vesting supply unallocated | Create and verify the intended beneficiary records before the applicable cutoff. |
| Assuming the token creator receives a new Fee Key | Check `platformLockNftWallet` and the actual migration record. Current migrations assign the combined locked share to the platform. |
| Assuming CPMM creator fees are enabled | Check `pool_creator`, `enable_creator_fee`, `creator_fee_on`, and `creator_fee_rate`. |
| Transferring a Fee Key unintentionally | The new holder controls future LP-fee collection. Verify the recipient before transferring it. |
