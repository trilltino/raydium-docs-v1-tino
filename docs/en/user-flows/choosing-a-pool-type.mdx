## The three pools in one paragraph

Raydium runs three AMM programs in parallel. **CPMM** is an `x · y = k` constant-product pool with full-range, fungible LP tokens and Token-2022 support. **CLMM** is a concentrated-liquidity pool where each position NFT has its own tick range and accrues fees only while that range is active. **AMM v4** is Raydium's original constant-product pool. Since the July 2026 upgrade, it no longer places or reads OpenBook orders.

For a side-by-side product-level comparison, see [`products/index`](/docs/en/products/index) and [`reference/fee-comparison`](/docs/en/reference/fee-comparison). This page helps you choose the creation flow before opening the CPMM, CLMM, or farm walkthrough.

## Selection flow

```text
Do you need a position with a custom price range?
  ├─ No  → CPMM: full-range liquidity and fungible LP tokens
  └─ Yes → CLMM: position NFT, selected ticks, range-dependent accrual

Already hold AMM v4 LP tokens?
  └─ Migration is optional. Both AMM v4 and CPMM now operate without OpenBook.

Need token incentives?
  └─ Create or use a compatible farm after selecting the pool.
```

## Mechanics matrix

| Requirement or behavior | CPMM | CLMM | AMM v4 |
|---|---|---|---|
| Position representation | Fungible LP tokens | Position NFT per range | Fungible LP tokens |
| Price range | Full range | Selected lower and upper ticks | Full range |
| Fee accrual | Pool reserves | Per-position accumulators while in range | Pool reserves and later PnL settlement |
| Token-2022 support | Supported within program constraints | Supported within program constraints | Not supported |
| OpenBook orders | None | None | Removed in July 2026 |
| Typical creation flow | [CPMM guide](/docs/en/user-flows/create-cpmm-pool) | [CLMM guide](/docs/en/user-flows/create-clmm-pool) | Existing integrations; CPMM is recommended for new constant-product pools |

LaunchLab is a token-launch flow, not another pool type in this decision. Newly initialized LaunchLab launches migrate to CPMM through the authorized migration path.

## Three questions to answer

### 1. Do you want to manage a price range?

CPMM liquidity remains active across the full price range. CLMM liquidity accrues new fees and rewards only while the current tick is inside the position's range. Moving a range requires a new liquidity operation; it does not happen automatically.

Concentration changes both fee exposure and impermanent loss. There is no universal multiplier for CLMM returns because the result depends on range width, active liquidity, volume, price movement, and time in range. See [`algorithms/impermanent-loss`](/docs/en/algorithms/impermanent-loss) for the math.

### 2. Which position and token mechanics do you need?

CPMM and AMM v4 use fungible LP tokens. CLMM uses an NFT for each position and range. Check the token program and supported extensions before choosing a pool; Token-2022 support does not mean every extension is accepted.

Farm support is a separate check. Do not assume a CLMM position NFT can be staked in a farm designed for fungible LP tokens.

### 3. Which fee configuration does the pool use?

Read the selected `AmmConfig` rather than relying on a generic tier list. The Raydium CPMM UI currently exposes `0.25%`, `0.3%`, `0.5%`, `1%`, `1.5%`, `2%`, `2.5%`, and `4%` configurations. Other configuration accounts can exist, and the live API is the source for currently available values.

Under the standard CPMM 0.25% configuration, LPs receive 84% of the trade fee, equivalent to 0.21% of volume. AMM v4's default economic LP equivalent is 0.22% of volume. A separate CPMM creator fee can also apply when enabled and configured with a nonzero rate; it does not come out of the LP trade-fee share.

A higher nominal fee does not guarantee higher LP income. Compare observed volume, active liquidity, time in range, and the complete fee configuration.

## CPMM vs CLMM in practice

### CPMM

- **Deposit:** two tokens at the current price ratio. Receive fungible LP tokens.
- **Earn:** fees compound into pool reserves; your LP share represents a claim on those reserves.
- **Withdraw:** burn LP tokens and receive your pro-rata share of reserves, subject to integer rounding and any mint transfer deductions.
- **Swaps:** the program exposes `SwapBaseInput` and `SwapBaseOutput`.
- **IL profile:** standard `x · y = k` IL. See [`algorithms/impermanent-loss`](/docs/en/algorithms/impermanent-loss).

### CLMM

- **Deposit:** two tokens, or one when the range requires only one side, for a specific `[tick_lower, tick_upper]` range. Receive a **position NFT**, not fungible LP tokens.
- **Earn:** fees accrue to the position while it is in range and do not auto-compound.
- **Collect:** use `DecreaseLiquidity` or `DecreaseLiquidityV2`. A zero-liquidity decrease collects without reducing position liquidity.
- **Close:** first reduce liquidity to zero and collect all pending fees and rewards. `ClosePosition` then closes the empty position; it does not collect nonzero balances itself.
- **Out of range:** the position stops new fee and reward accrual and becomes fully one-sided. You remain exposed to the asset it holds.

### AMM v4

- **Deposit:** two tokens at the current pool ratio. Receive fungible LP tokens.
- **Earn:** the whole swap fee initially remains in pool reserves. Protocol PnL is realized separately under the pool's current parameters.
- **Withdraw:** burn LP tokens for the underlying reserves. No OpenBook orders are unwound.
- **OpenBook history:** the removed hybrid design is historical. The `market` key used by current pool creation is an address seed, not a live orderbook connection.

See [`products/amm-v4/overview`](/docs/en/products/amm-v4/overview) for the current program model.

## Worked fee-APR example

This example compares only CPMM and AMM v4 because their pool-wide liquidity inputs are sufficient for a simple calculation.

Assume:

- You supply \$10,000.
- Projected 30-day volume is \$150M.
- CPMM pool TVL is \$50M and uses the standard 0.25% fee with an 84% LP share.
- AMM v4 pool TVL is \$30M and uses its default 0.22% LP economic equivalent.
- Volume and TVL remain constant, and you do not compound.

```text
CPMM 30-day fees = $150M × 0.25% × 84% × ($10k / $50M) = $63
CPMM simple APR  = ($63 / $10,000) × (365 / 30) = 7.665%

AMM v4 30-day fees = $150M × 0.22% × ($10k / $30M) = $110
AMM v4 simple APR  = ($110 / $10,000) × (365 / 30) = 13.383%
```

These are arithmetic examples, not return forecasts. They exclude price changes, impermanent loss, compounding, and any separate CPMM creator fee. CLMM needs additional active-liquidity and time-in-range inputs, so the same TVL formula cannot produce a defensible CLMM APR. Use [`algorithms/clmm-apr`](/docs/en/algorithms/clmm-apr) for that calculation.

## Common mistakes

- **"CLMM always earns more."** Only in-range liquidity accrues new fees and rewards, and concentration also changes IL.
- **"Tighter range means more total fees."** A tighter range can increase fee exposure per unit of active liquidity while in range, but it can also spend more time out of range.
- **"A higher fee tier guarantees more income."** Volume, active liquidity, and trader routing also matter.
- **"LP tokens and position NFTs are interchangeable."** They have different account models and farm compatibility.
- **"AMM v4 still requires OpenBook."** Current AMM v4 rejects the removed orderbook instructions and ignores legacy market accounts during swaps.
