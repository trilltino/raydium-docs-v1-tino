## How Anchor error codes work

Anchor assigns each variant of a program's `ErrorCode` enum a numeric code starting at `6000`. A failing transaction surfaces:

- **Numeric error code** (e.g. `0x1771` = 6001) in the transaction logs.
- **Error name** (e.g. `InvalidOwner`) from the IDL.
- **`#[msg(...)]` string** that Anchor emitted in `log_messages`.

Integrators should match on the **numeric code**, not the message string (the string can be re-worded without bumping a version).

```ts
// Example: detect the CPMM slippage error and surface a clean UX message.
const CPMM_EXCEEDED_SLIPPAGE = 6005;

try {
  await sdk.cpmm.swap({ ... });
} catch (err: any) {
  const code = err?.error?.errorCode?.number ?? err?.code;
  if (code === CPMM_EXCEEDED_SLIPPAGE) {
    showToast("Price moved past your slippage tolerance. Increase slippage or retry.");
    return;
  }
  throw err;
}
```

> **Note on renumbering.** The CLMM `ErrorCode` enum was renumbered in this release: five legacy variants (`LOK`, `ZeroMintAmount`, `InvalidLiquidity`, `TransactionTooOld`, `InvalidRewardDesiredAmount`) and several typos (`Liquitity`, `enought`, `emissiones`) were removed/fixed, and eleven new variants were appended (`6040`–`6050`) by the limit-order release; `6051` (`InvalidTickArrayBitmapExtensionAccount`) came from a separate, later change. That made 52 variants, `6000`–`6051`, which is the count the currently deployed program's on-chain IDL reports. The [2026-09-30 upgrade](/docs/en/reference/changelog/2026-09-30-clmm-anchor-1-and-excess-lamports) appends `6052` without shifting anything, for 53 in total. Because Anchor numbers errors by source order, every code at or after `6000` has shifted relative to pre-release builds. Clients that hard-coded numeric codes against an earlier version need to remap.

`6020` is retained deliberately. Anchor numbers variants by position, so deleting it would shift every code after it and break every client that decodes `6021`–`6031`.

### AMM v4: `AmmError` is not Anchor-numbered

AMM v4 predates Anchor. `AmmError` is a plain `thiserror` enum with `FromPrimitive`, converted through `ProgramError::Custom(e as u32)`, so its codes start at **`0`**, not `6000` — and, like Anchor's, are assigned by source order. The 2026-09 upgrade appends one variant:

| Code | Variant | `#[error]` string | Cause |
|---|---|---|---|
| 60 | `LamportsCalculateError` | Lamports calculate error. | `WithdrawExcessLamports` swept a wrapped-SOL account and the `SyncNative` → `UnwrapLamports` round-trip did not leave the wrapped token balance exactly where it started. Admin-only path. |

Codes `0`–`59` are unchanged, so nothing shifts. In transaction logs this surfaces as `custom program error: 0x3c`. Regeneration source: [github.com/raydium-io/raydium-amm — error.rs](https://github.com/raydium-io/raydium-amm/blob/master/program/src/error.rs).

## Mapping SDK errors to program errors

The official TypeScript SDK wraps on-chain errors into `SendTransactionError` and, for Anchor programs, `AnchorError`:

```ts
import { AnchorError } from "@anchor-lang/core";

try {
  await sdk.cpmm.swap({ ... });
} catch (err) {
  if (err instanceof AnchorError) {
    console.log(err.error.errorCode.number, err.error.errorCode.code, err.error.errorMessage);
    // 6005 ExceededSlippage "Exceeds desired slippage limit"
  } else {
    // Raw SendTransactionError — inspect err.logs for the "custom program error: 0x..." line.
  }
}
```

If you are not using Anchor client-side, parse the transaction logs:

```
Program <ProgramID> invoke [1]
Program log: AnchorError caused by account: pool_state. Error Code: ExceededSlippage. Error Number: 6005. Error Message: Exceeds desired slippage limit.
```

The pattern `Error Number: (\d+)` is stable across Anchor versions and safe to match.

## Regenerating these tables

When a program is upgraded and adds a new error, re-extract from source:

```bash
# Clone and grep the error enum in order.
git clone --depth=1 https://github.com/raydium-io/raydium-cp-swap
awk '/#\[msg\(/{ gsub(/^[ \t]*#\[msg\("|"\)\][ \t]*/,""); m=$0; getline; gsub(/,/,""); gsub(/^[ \t]+/,""); print "6000+++\t" $0 "\t" m }' \
  raydium-cp-swap/programs/cp-swap/src/error.rs
# Replace 6000+++ with monotonically-increasing 6000,6001,... Append new rows to the table above.
```

Always update [`reference/changelog`](/docs/en/reference/changelog) when a new variant is added, so integrators upgrading the SDK know to refresh their error handlers.
